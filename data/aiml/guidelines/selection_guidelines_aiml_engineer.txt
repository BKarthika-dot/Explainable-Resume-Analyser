INTENDED USE
This document provides structured criteria for evaluating resumes
for the AI/ML Engineer role across all seniority levels. It is
designed for use in an AI-powered RAG-based screening system and
human review. The system automatically detects experience level and
routes candidates to the appropriate track and sub-tier. Scores are
advisory; final decisions rest with the hiring panel.

----------------------------------------------------------------
SECTION 1: AUTOMATED ROUTING & SCORING FRAMEWORK
----------------------------------------------------------------

STEP 1 — EXPERIENCE PARSING
The system parses total non-academic, industry-grade experience
(internships count as 0.5x weight unless backed by verifiable
publication, patent, or shipped product evidence).

  Total Experience < 1 Year    ➔  TRACK C : INTERN / FRESHER
  Total Experience 1–3 Years   ➔  TRACK B : JUNIOR / ASSOCIATE
  Total Experience 3–7 Years   ➔  TRACK A : MID / SENIOR
  Total Experience > 7 Years   ➔  TRACK S : STAFF / PRINCIPAL

STEP 2 — SPECIALIZATION SIGNAL DETECTION
The system also flags optional specialization signals in the resume
to annotate the evaluation output (does NOT change track routing):
  [LLM]  : Large Language Model / GenAI focus detected
  [CV]   : Computer Vision focus detected
  [MLO]  : MLOps / Platform Engineering focus detected
  [RS]   : Research Scientist profile detected
  [DS]   : Data Science / Analytics hybrid detected

SECTION 3: TRACK C — INTERN / FRESHER CRITERIA (< 1 Year)
----------------------------------------------------------------

CRITICAL POLICY: Do NOT penalize Track C candidates for missing
production deployments, pipeline tooling, or enterprise system
ownership. Evaluate raw programming ability, mathematical intuition,
independent initiative, and learning velocity.

──────────────────────────────────────────────────────────────
DIMENSION 1: PYTHON ENGINEERING & OOP DEPTH (Max 30 pts)
──────────────────────────────────────────────────────────────

25–30 pts  [Expert Fresher]
  Masters Object-Oriented design patterns (classes, encapsulation,
  inheritance, polymorphism). Writes modular, reusable function
  libraries. Uses list comprehensions, generators, and context
  managers fluently. Demonstrates clean file I/O, error handling,
  and test-driven structure. No evidence of copy-paste scripting.
  Bonus signal: contributions to open-source Python packages.

15–24 pts  [Functional]
  Understands basic programming constructs. Can build multi-function
  scripts but lacks structural modularity or clean encapsulation.
  Relies on notebooks rather than .py module files.

0–14 pts   [Superficial]
  Struggles to articulate programmatic data flow. Evidence limited
  to tutorial reproductions without modification or understanding.

──────────────────────────────────────────────────────────────
DIMENSION 2: MATHEMATICAL & ALGORITHMIC FOUNDATION (Max 25 pts)
──────────────────────────────────────────────────────────────

21–25 pts  [Strong]
  Deep grasp of linear algebra (matrix decompositions, eigenvalues),
  multivariate calculus (partial derivatives, chain rule application
  in backprop), probability distributions (Bayesian inference,
  MLE), and gradient-based optimization mechanics. Can derive and
  explain loss function behavior without prompt.

12–20 pts  [Adequate]
  Memorized algorithmic keywords and surface-level formula recall.
  Struggles to explain why specific optimizers converge differently
  or how regularization alters the loss surface.

0–11 pts   [Weak]
  Pure black-box developer. Cannot explain gradient descent, cost
  function curvature, or statistical inference. Disqualifying for
  roles requiring model customization.

──────────────────────────────────────────────────────────────
DIMENSION 3: PREDICTIVE MODELING & DATA PREPROCESSING (Max 20 pts)
──────────────────────────────────────────────────────────────

17–20 pts  [Strong Pipeline Builder]
  Demonstrates clean model pipeline construction using Scikit-Learn
  or PyTorch. Correctly applies feature transformations, handles
  class imbalances (SMOTE, class weighting), uses stratified k-fold
  cross-validation, and evaluates using robust metrics beyond
  accuracy: ROC-AUC, F1-macro, Precision-Recall curves. Shows
  awareness of data leakage prevention.

10–16 pts  [Standard]
  Relies on textbook boilerplate datasets (Titanic, Iris, MNIST)
  with default parameters and minimal feature engineering. Metrics
  restricted to accuracy or loss. Limited preprocessing steps.

0–9 pts    [Insufficient]
  No proof of independent model execution, transformation pipelines,
  or reproducible evaluation. Google Colab tutorials only.

──────────────────────────────────────────────────────────────
DIMENSION 4: PROJECTS, INTERFACES & DEPLOYMENT PROOF (Max 15 pts)
──────────────────────────────────────────────────────────────

12–15 pts  [Standout Portfolio]
  Built at least one genuinely original project: healthcare model
  with SHAP explainability, recommendation system deployed via
  Streamlit or FastAPI, NLP classifier with custom preprocessing, or
  audio classification system. Shows understanding of API routing or
  basic database queries. GitHub repo has a structured README, clean
  commit history, and reproducible setup.

6–11 pts   [Basic]
  Follow-along repository structures from tutorials. Minimal
  independent data engineering or unique feature additions.
  No deployment evidence. README absent or boilerplate.

0–5 pts    [Missing]
  No verifiable code repositories or independent implementation
  projects. No GitHub link or empty profile.

──────────────────────────────────────────────────────────────
DIMENSION 5: EDUCATION, GPA & CERTIFICATIONS (Max 10 pts)
──────────────────────────────────────────────────────────────

9–10 pts   B.Tech / B.E. / M.Tech / MCA in CS, IT, AI, or related
           fields with CGPA >= 7.5/10 from recognized institutions,
           OR industry certifications: AWS ML Specialty, GCP
           Professional ML Engineer, DeepLearning.AI Specialization,
           Fast.ai Practical Deep Learning.

5–8 pts    Allied quantitative disciplines (ECE, EEE, Statistics)
           with strong analytics coursework or AI certifications
           from recognized MOOC providers.

0–4 pts    Non-technical track with no compensating practical or
           certification evidence.

SECTION 4: TRACK B — JUNIOR / ASSOCIATE CRITERIA (1–3 Years)
----------------------------------------------------------------

──────────────────────────────────────────────────────────────
DIMENSION 1: CORE ML FRAMEWORK & MODELING DEPTH (Max 25 pts)
──────────────────────────────────────────────────────────────

1A. Algorithm & Architecture Breadth (0–15 pts)
  15 pts : Independently implements supervised (gradient boosting,
           neural architectures), unsupervised (clustering, dim
           reduction), and basic sequence models (RNNs, basic
           Transformers). Understands tradeoffs between algorithms
           and selects appropriately for problem type. Uses PyTorch
           or TensorFlow with custom training loops, not just
           fit/predict wrappers.
  10–14  : Strong command of standard supervised algorithms.
           Implements multi-layer architectures but relies on
           framework defaults for optimization and regularization.
   5–9   : Applied modeling using standard library parameters.
           Limited exposure beyond classification and regression.
   0–4   : Restricted to tutorial-grade implementations with no
           awareness of model tradeoffs.

1B. Data Engineering for ML (0–6 pts)
  6 pts  : Builds feature pipelines from raw, messy data.
           Handles missing values with strategy selection (not
           just mean-fill). Engineers time-series lag features,
           text embeddings, or categorical encoding beyond
           one-hot. Manages class imbalances. Familiar with
           Pandas, NumPy, and at least one of: Spark, Dask,
           Polars for larger-scale data.
  3–5    : Comfortable with standard preprocessing steps on
           structured data. Limited exposure to NLP or
           time-series specific pipelines.
  0–2    : Relies strictly on clean, pre-formatted tutorial
           datasets. No evidence of real-world preprocessing.

1C. SQL & Data Access (0–4 pts)
  4 pts  : Constructs complex multi-table joins, CTEs, window
           functions, and aggregation pipelines to build feature
           stores. Comfortable with query optimization basics.
  2–3    : Intermediate SQL; can write multi-table inner joins
           and GROUP BY aggregations.
  0–1    : Minimal or no SQL; relies on pre-extracted file
           formats only.

──────────────────────────────────────────────────────────────
DIMENSION 2: WORK EXPERIENCE QUALITY & OWNERSHIP (Max 20 pts)
──────────────────────────────────────────────────────────────

2A. Role Relevance (0–8 pts)
  8 pts  : 1–3 years directly as ML Engineer, Data Scientist,
           or AI Engineer at a product-grade technology company
           or AI-focused startup. Clear evidence of working on
           real production data (not internal sandbox demos).
  5–7    : 1+ years relevant technical experience with partial
           ML exposure; or strong internship series at known
           technology organizations.
  0–4    : General software engineering with incidental
           scripting tasks only. No ML model ownership evidence.

2B. Quantified Business Impact (0–7 pts)
  7 pts  : Multiple quantified outcomes: model precision improved
           by X%, prediction latency reduced by Yms, churn
           prediction saving $Z/quarter, or recommendation click-
           through rate increased by W%. Numbers tied to business
           metric, not just model benchmark.
  4–6    : At least one clear outcome metric from a production
           or near-production ML integration.
  0–3    : Purely task-oriented descriptions ("trained a model",
           "built a classifier") with no evaluation of real-world
           impact.

2C. Technical Scope & Ownership (0–5 pts)
  5 pts  : Independently scoped and delivered at least one ML
           feature end-to-end: data sourcing → preprocessing →
           training → evaluation → deployment or handoff.
           Communicated trade-offs to non-technical stakeholders.
  3–4    : Strong independent contributor; relied on a senior
           engineer for scoping but executed independently.
  0–2    : Executed isolated subtasks only. No ownership of a
           complete model workflow.

──────────────────────────────────────────────────────────────
DIMENSION 3: STATISTICAL RIGOR & MODEL EVALUATION (Max 20 pts)
──────────────────────────────────────────────────────────────

3A. Evaluation Methodology (0–12 pts)
  12 pts : Goes well beyond train/test split. Uses stratified
           k-fold CV, calibration curves (reliability diagrams),
           bootstrapped confidence intervals, threshold tuning
           via precision-recall tradeoff analysis, and multi-
           class metrics (macro/weighted F1). Aware of and tests
           for data leakage. Detects and acts on distribution
           shift in validation sets.
  7–11   : Standard cross-validation and confusion matrix
           reporting. Uses AUC-ROC but does not tune thresholds
           or examine calibration.
  2–6    : Relies on training accuracy as primary metric.
           Minimal understanding of overfitting detection beyond
           train/val gap.
  0–1    : No rigorous evaluation framework visible.

3B. Statistical Foundations (0–8 pts)
  8 pts  : Comfortable with hypothesis testing (t-tests, Mann-
           Whitney, chi-square), distribution fitting, A/B test
           significance calculations, and Bayesian updating.
           Understands p-value misinterpretation pitfalls. Uses
           statistical tests to validate feature importance.
  4–7    : Aware of basic statistical testing. Can describe
           hypothesis testing but inconsistently applies it.
  0–3    : Statistical knowledge limited to descriptive
           statistics and correlation coefficients only.

──────────────────────────────────────────────────────────────
DIMENSION 4: ENGINEERING PRACTICES & CODE QUALITY (Max 15 pts)
──────────────────────────────────────────────────────────────

4A. Software Engineering Standards (0–8 pts)
  8 pts  : Writes modular, PEP-8 compliant Python code organized
           into packages (not monolithic notebooks). Uses virtual
           environments, requirements files, and config management
           (YAML / .env). Writes unit tests for data pipelines
           and model utilities. Code reviews mentioned in work
           experience. Familiar with CI/CD basics (GitHub Actions,
           pre-commit hooks).
  4–7    : Uses Git regularly. Organizes code beyond single
           script files. Some awareness of environment management
           and code structure best practices.
  0–3    : Notebook-only or script-only work. No version control
           evidence or reproducibility setup.

4B. Model Serving & Basic Deployment (0–7 pts)
  7 pts  : Has wrapped at least one model in a REST API (FastAPI,
           Flask) with request validation. Understands latency
           vs. throughput tradeoffs. Familiar with Docker basics
           and container-based serving. Exposed models to internal
           consumers or production-grade integrations.
  3–6    : Has served model outputs via a simple API or Streamlit
           app. No container or cloud deployment evidence.
  0–2    : Local execution only. No integration with network-
           accessible interfaces or web frameworks.

──────────────────────────────────────────────────────────────
DIMENSION 5: PROJECTS, PORTFOLIOS & OPEN CONTRIBUTIONS (Max 12 pts)
──────────────────────────────────────────────────────────────

10–12 pts  Independent, original projects with measurable scope:
           a fine-tuned LLM for domain-specific QA, a custom
           object detector on self-collected data, a multi-model
           A/B experimentation framework, or a deployed web tool
           with live ML inference. Kaggle competition placement
           (top 20%) or open-source PR merged into known library.
           GitHub demonstrates clean coding habits, documentation,
           and regular activity.

5–9 pts    One or two follow-along projects extended with original
           components. GitHub active but mostly forked repositories.
           No external recognition or deployment.

0–4 pts    Minimal public portfolio. GitHub empty or last commit
           > 12 months ago. Projects are unverifiable or
           entirely derivative.

──────────────────────────────────────────────────────────────
DIMENSION 6: EDUCATION & CREDENTIALS (Max 8 pts)
──────────────────────────────────────────────────────────────

7–8 pts    M.Tech / M.S. / M.Sc. in CS, AI, Data Science from
           recognized institution, OR B.Tech from IIT, NIT, BITS,
           or international equivalent with CGPA >= 8.0/10.
           Industry certs: AWS ML Specialty, GCP ML Engineer,
           TensorFlow Developer, Azure AI Engineer, or equivalent.

4–6 pts    B.Tech / B.E. from tier-2 institutions with CGPA
           >= 7.0/10. MOOC-based certifications from DeepLearning.AI,
           Fast.ai, or Coursera Machine Learning Specialization.

0–3 pts    Unrelated degree with no compensating experience or
           certification. CGPA below 7.0 or undeclared with no
           other signals.

SECTION 5: TRACK A — MID / SENIOR CRITERIA (3–7 Years)
----------------------------------------------------------------

──────────────────────────────────────────────────────────────
DIMENSION 1: CORE MODELING DEPTH & FRAMEWORK MASTERY (Max 22 pts)
──────────────────────────────────────────────────────────────

1A. Algorithm Expertise (0–14 pts)
  14 pts : Production deployment of complex model architectures:
           Transformer variants (BERT, T5, LLaMA-family fine-tuning),
           robust ensemble methods with custom objective functions
           (XGBoost, LightGBM with custom losses), diffusion
           models, or graph neural networks. Deep understanding
           of regularization (dropout scheduling, weight decay,
           spectral normalization), hyperparameter search (Optuna,
           Ray Tune), and learning rate schedules. Clear evidence
           of performance engineering at scale (mixed-precision,
           model pruning, quantization).
  10–13  : Independent expert in supervised and deep learning
           algorithms. Strong parameter evaluation and custom
           architecture work.
   5–9   : Applied modeling using standard configurations with
           limited custom tuning.
   0–4   : Shallow modeling footprint; relies on out-of-the-box
           configurations.

1B. Data at Scale (0–5 pts)
  5 pts  : Designed data pipelines handling TB-scale datasets
           (Spark, Beam, or distributed preprocessing). Managed
           extreme class imbalances, synthetic data generation
           (SMOTE, GANs, augmentation policies), complex joins
           across distributed sources, and streaming data ingestion
           for online learning.
  3–4    : Comfortable with moderate-scale pipelines. Standard
           preprocessing and feature store interactions.
  0–2    : Works primarily with preprocessed, in-memory datasets.

1C. Querying & Feature Stores (0–3 pts)
  3 pts  : Builds optimized feature store queries (Feast, Hopsworks,
           or custom BigQuery / Redshift feature tables). Writes
           complex window functions and temporal joins for time-
           aware feature engineering.
  1–2    : Proficient SQL for analytics. No feature store
           architecture experience.
  0      : No SQL or data warehouse exposure.

──────────────────────────────────────────────────────────────
DIMENSION 2: WORK EXPERIENCE QUALITY & BUSINESS IMPACT (Max 20 pts)
──────────────────────────────────────────────────────────────

2A. Role Relevance & Seniority Signal (0–8 pts)
  8 pts  : 3+ years as AI/ML Engineer, Applied Scientist, or
           Senior Data Scientist at a product-grade organization.
           Evidence of direct ownership over model versioning,
           retraining pipelines, and production deployment cycles.
  5–7    : 2–3 years directly relevant ML experience with evidence
           of end-to-end ownership. Strong engineering background
           transitioning into ML with advanced depth.
  0–4    : Primarily software engineering with incidental model
           integration. Low ML ownership signal.

2B. Quantified Business & Model Outcomes (0–7 pts)
  7 pts  : Multiple quantified, business-contextualized metrics:
           revenue uplift ($X from recommender), latency reduction
           (Yms p99), precision improvement leading to reduced
           false positives at a stated cost, or safety improvement
           in a regulated environment. Demonstrates awareness of
           model ROI and business justification.
  4–6    : Clear outcome metrics from at least one production
           integration. Numbers present but not fully contextualized.
  0–3    : Task-oriented descriptions without production metrics
           or business outcome linkage.

2C. System Ownership & Cross-Functional Depth (0–5 pts)
  5 pts  : Proven ownership from ideation to production.
           Mentored junior engineers. Drove model selection debates
           with documented trade-off analyses. Ran retrospectives
           on model failures. Coordinated with product, data, and
           infrastructure teams.
  3–4    : Strong contributor. Independently delivered features
           but limited evidence of cross-team coordination.
  0–2    : Confined to execution of assigned subtasks. No
           visible cross-functional ownership.

──────────────────────────────────────────────────────────────
DIMENSION 3: EXPLAINABLE AI, FAIRNESS & INTERPRETABILITY (Max 18 pts)
──────────────────────────────────────────────────────────────

3A. Explainability Frameworks (0–10 pts)
  10 pts : Active deployment of model interpretability in
           production: SHAP value analysis for feature auditing,
           LIME for local explanations in high-stakes domains,
           Integrated Gradients for deep model debugging, or
           attention visualization for Transformer models.
           Has used explainability to detect and correct feature
           leakage, model bias, or distribution drift. Documents
           decisions for regulatory or compliance contexts.
  6–9    : Strong integration of SHAP/LIME during model evaluation.
           Produces summary plots and feature dependency analyses
           as part of standard workflow.
  2–5    : Theoretical awareness. Minor notebook-level
           implementation without production application.
  0–1    : No explainability footprint. Treats all models as
           pure black-box systems.

3B. Fairness, Bias & Safety Awareness (0–4 pts)
  4 pts  : Proactively audits models for demographic parity,
           equalized odds, or calibration fairness. Familiar with
           frameworks: Fairlearn, AI Fairness 360, or custom
           disparity analysis. Raised or documented concerns about
           model outputs in sensitive domains.
  2–3    : Mentions bias awareness but no demonstrated mitigation
           workflow.
  0–1    : No fairness or safety signal in documented work.

3C. Statistical Evaluation Rigor (0–4 pts)
  4 pts  : Uses parametric and non-parametric hypothesis testing
           to validate model improvements (McNemar's test, DeLong
           test for AUC comparison). Monitors data drift using
           distribution distance metrics (PSI, KS statistic,
           Jensen-Shannon divergence). Designs multi-armed
           experimentation frameworks (A/B, multi-bandit).
  2–3    : Standard cross-validation and confusion matrix analysis.
           Basic distribution monitoring.
  0–1    : Weak validation logic; no statistical rigor in model
           comparison.

──────────────────────────────────────────────────────────────
DIMENSION 4: MLOPS, PRODUCTION SYSTEMS & SCALE (Max 18 pts)
──────────────────────────────────────────────────────────────

4A. Serving, APIs & Microservices (0–8 pts)
  8 pts  : Deep mastery of model serving architectures: FastAPI /
           Triton Inference Server / TorchServe / BentoML with
           Docker + Kubernetes orchestration. Implements batch and
           real-time inference endpoints. Optimizes for throughput
           (async batching) and latency (model quantization, TensorRT,
           ONNX export). Manages blue-green or canary deployments.
  4–7    : Competent API wrapping and container deployment. REST
           endpoints with basic scaling configuration.
  0–3    : Local or notebook-only execution. No container or
           network service integration.

4B. Experiment Tracking & Pipeline Orchestration (0–6 pts)
  6 pts  : Proficient with MLflow, Weights & Biases, or DVC for
           full experiment lifecycle management (params, artifacts,
           metrics, model registry). Uses pipeline orchestration
           tools (Airflow, Prefect, Kubeflow Pipelines, ZenML) for
           automated retraining triggers. Manages feature stores
           (Feast, Tecton) or vector stores (Pinecone, Weaviate,
           Qdrant) for LLM RAG applications.
  3–5    : Git + DVC for version control. MLflow for basic
           experiment tracking. No pipeline orchestration depth.
  0–2    : Ad-hoc tracking. Missing structural reproducibility
           or automated retraining pipelines.

4C. Monitoring & Reliability (0–4 pts)
  4 pts  : Implements model monitoring in production: input drift
           detection, output distribution shifts, prediction
           confidence degradation, and automated retraining triggers.
           Familiar with observability tooling (Prometheus, Grafana,
           Evidently AI, or Arize AI). Designs SLA-backed inference
           contracts.
  2–3    : Basic logging of model predictions. No automated
           alerting or drift detection.
  0–1    : No monitoring framework. Reactive incident response
           only.

──────────────────────────────────────────────────────────────
DIMENSION 5: SYSTEM DESIGN & CROSS-FUNCTIONAL OWNERSHIP (Max 10 pts)
──────────────────────────────────────────────────────────────

8–10 pts   Can design end-to-end ML systems: data ingestion →
           feature engineering → training pipeline → model
           registry → serving layer → monitoring → feedback loop.
           Accounts for throughput requirements, SLA targets,
           cold-start handling, and graceful degradation. Has
           documented system design artifacts (architecture
           diagrams, design docs, or RFCs).

5–7 pts    Understands major components of ML system architecture
           but has not independently designed a full-stack system.
           Can describe trade-offs between design options.

0–4 pts    Limited systems thinking. Focus restricted to isolated
           model training without upstream or downstream awareness.

──────────────────────────────────────────────────────────────
DIMENSION 6: EDUCATION, CREDENTIALS & PUBLICATIONS (Max 7 pts)
──────────────────────────────────────────────────────────────

6–7 pts    M.S. / M.Tech / Ph.D. in CS, AI, Statistics, or
           related from IIT, IISc, NIT, BITS, or equivalent
           international program. OR peer-reviewed publications
           (NeurIPS, ICML, CVPR, ACL, EMNLP, ICLR, KDD, WWW).
           Industry-recognized certifications as secondary signal.

4–5 pts    B.Tech from top-tier institution with CGPA >= 8.0 and
           strong academic project output. Advanced certifications
           from AWS, GCP, or Databricks.

2–3 pts    Solid engineering degree from tier-2 institution with
           strong compensating industry experience.

0–1 pts    Unrelated specialization without compensating depth.
           CGPA below 7.0 or undeclared with no other signal.

──────────────────────────────────────────────────────────────
DIMENSION 7: PORTFOLIO, RESEARCH & OPEN SOURCE (Max 5 pts)
──────────────────────────────────────────────────────────────

5 pts      Active open-source contributions to major ML libraries
           (HuggingFace, Scikit-Learn, PyTorch, LangChain). Kaggle
           Grandmaster / Master rank. Published technical blog posts
           (widely cited). Conference talks or workshops delivered.

3–4 pts    Notable Kaggle competition finishes (top 10%). Multiple
           original GitHub projects with documented experiments and
           clean code standards. Technical writing.

0–2 pts    Minimal public footprint beyond standard employment.
           No recognizable community or research presence.

----------------------------------------------------------------
SECTION 6: TRACK S — STAFF / PRINCIPAL CRITERIA (> 7 Years)
----------------------------------------------------------------

Note: Track S evaluates leverage, vision, and strategic impact
above raw technical execution. A candidate who scores high on
individual contribution but shows no multiplier effect on teams
or systems should be mapped to Track A (Senior) regardless of
tenure. Evaluate depth AND organizational scale.

──────────────────────────────────────────────────────────────
DIMENSION 1: TECHNICAL VISION & RESEARCH OUTPUT (Max 20 pts)
──────────────────────────────────────────────────────────────

16–20 pts  Has shaped the direction of ML capability at an
           organization level: authored technical roadmaps,

SECTION 7: HARD DISQUALIFIERS — UNIVERSAL BYPASS FILTERS
----------------------------------------------------------------

These conditions immediately flag a resume for rejection review
regardless of track, score, or seniority level.

  □ Complete absence of Python or any programming evidence.
    This role requires custom development capability at all levels.

  □ Purely click-and-run UI profiles (AutoML without code,
    drag-and-drop tools only) with no underlying engineering
    architecture demonstrated.

  □ Fabricated academic credentials, certifications, project
    metrics, or employment dates. Cross-verify GitHub activity
    timestamps against claimed project dates.

  □ No verifiable output: no public GitHub, no referenced
    deployment, no named company, no publication, no citation.
    Entirely unverifiable resumes above Track C require escalation.

  □ Track A / S only: Claimed 5+ years but no evidence of
    production model ownership (no serving infrastructure,
    no retraining pipelines, no monitoring frameworks referenced).

  □ Evident plagiarism in listed project descriptions matching
    known Kaggle kernels or public tutorial repositories verbatim
    without acknowledgement.

SECTION 10: BENCHMARK CALIBRATION GUIDANCE
----------------------------------------------------------------

These calibration notes help normalize scores across evaluators
and ensure FAANG-equivalent bar alignment.

TRACK C (Intern/Fresher) — Calibration:
  A score of 80+ should be genuinely exceptional: a fresher who
  can implement a clean PyTorch training loop from scratch,
  explain gradient descent with mathematical detail, and has
  independently deployed a model to a public endpoint. Do not
  award 80+ for a well-organized Jupyter notebook.

TRACK B (Junior) — Calibration:
  A score of 85+ requires quantified production experience, not
  just self-hosted projects. Clean code, a deployment story,
  and measurable model impact are the bar. Do not elevate into
  this band based solely on educational credentials.

TRACK A (Senior) — Calibration:
  A score of 88+ should be reserved for candidates who could
  be immediately productive and influential. They should have
  owned a production ML system, have measurable business impact,
  and demonstrate some form of broader technical leadership.
  At this level, missing explainability or monitoring experience
  is a significant gap, not a minor one.

TRACK S (Staff/Principal) — Calibration:
  Fewer than 1 in 10 applicants claiming Staff/Principal titles
  will score above 75. The bar is not deep individual skill —
  it is documented evidence of organizational leverage, system
  architecture at scale, and reproducible leadership outcomes.
  Technical brilliance without leadership or external signal
  should be downgraded to Track A (Senior).

INTER-TRACK ESCALATION:
  If a Track B or Track C candidate shows overwhelming positive
  signals (e.g., published author, Kaggle Grandmaster, open-source
  maintainer with 1K+ stars), the evaluator may escalate the
  routing level with a written justification in evaluator_notes.
